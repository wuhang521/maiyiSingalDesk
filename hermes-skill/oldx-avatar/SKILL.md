# OLDX Avatar：文案变成会说话的人

## 阶段确认钩子（Hermes 默认）

Hermes 本机默认 `TASK_VIDEO_COST_REVIEW_REQUIRED=0`，在 **文案与人物图 → 配音试听 → 生成方案与范围 → 成片效果** 四站展示产物并记录实际确认。确认生成范围后，用户点击生成，API 用 `generation_consent=true` 记录本次意图，再按整条真实配音的实际分段执行；不估价、不输入预算金额、不设置费用复选框。首次云端制作前只提示一次“云端生成按服务商规则计费。”

执行方式见 [references/review-hooks.md](references/review-hooks.md)，制作或继续旧项目时先读。素材或参数变化后对应确认失效；新生成批次重新确认方案与范围。用户明确跳过某站创作审核时，只记录真实原话和当前版本，不重复询问；跳过审核不代替新任务的生成操作。本约定优先于下文历史指南中的费用步骤、自动重试及“直接进入下一阶段”。

## Hermes 可移植运行约定

- 本副本由 Hermes 后端受控适配器执行，Python 解释器通过 `TASK_VIDEO_PYTHON` 指定；技能位置可用 `TASK_VIDEO_SKILL_DIR` 覆盖。项目保存在 `TASK_VIDEO_STORAGE_DIR`，不依赖 Codex 用户目录。
- 密钥由部署环境 `DASHSCOPE_API_KEY`、`RUNNINGHUB_API_KEY` 或受控的 `BL_KEY_FILE`、`RH_KEY_FILE` 提供，不复制到技能包或日志。
- 当前本机直接生成先校验方案版本、阶段确认、固定范围与本次 `generation_consent`；不调用报价接口，也不要求费用授权。旧金额预算仅在显式开启 `TASK_VIDEO_COST_REVIEW_REQUIRED=1` 的兼容部署中使用。
- 四个阶段确认由 Hermes 当前方案版本中真实用户批准或明确跳过的记录映射，`--yes` 不代替确认，也不编造批准原话。
- 人物视频覆盖整条项目配音，展示实际总时长及自动分段数，不称为“生成当前镜头”。默认可用千问系统声音，无需克隆样本；跳剪和字幕按已确认选项执行，数字人默认两项关闭。去停顿前须确认当前原片，完成后重新验收成片。
- 普通视频由 Hermes 的 `video-production` 入口调用火山官方 Seedance 2.0 Mini：北京接口 `https://ark.cn-beijing.volces.com/api/v3`、模型 `doubao-seedance-2-0-mini-260615`，优先复用 Hermes 原独立 Ark 视频凭证。本技能负责数字人，保持 OLDX RunningHub 工作流和原企业共享 Key，不将数字人底层模型称为 Seedance。策划仍复用 Hermes 模型，千问配音及识别保持 Hermes 的 DashScope 凭证。新任务固定生成参数和幂等键；旧 RunningHub/Ark 回执按原通道恢复，模糊提交、失败或下载错误不自动重复生成，也不切换供应商重发。
- 不自动安装依赖或读取其他用户主目录；部署者在专用 Python 环境预装依赖。原作者历史授权不作为当前用户授权。
- 本节优先于下文历史指南中“自动安装依赖”“将密钥粘贴到聊天”“直接授权实例”的运行建议；Hermes 仅通过受控后端和安全环境配置执行。详细部署及恢复见 [HERMES-RUNTIME.md](HERMES-RUNTIME.md)。
- 医疗内容经用户真实确认当前方案并点击生成后，按普通阶段制作，不要求医疗资质或专业审稿证明，不增加额外必需确认。核对事实来源，专业医学审稿仅作可选建议；不虚构医生身份或已审结论，不将内容确认冒充专业审核。真实肖像和声音授权仍需保留。

## 历史独立运行指南的适用范围

以下保留原作者独立运行方式，便于追踪旧项目和脚本参数；其中要声音样本、自动安装、报费用、直接命令及默认跳剪等步骤，只适用于非 Hermes 独立运行，或明确启用的 legacy 模式。Hermes 本机操作始终按上方约定及 `HERMES-RUNTIME.md` 执行，不得用历史指南覆盖无报价流程、后处理选择或授权要求。

把一段文案做成一条数字人视频：声音是用户自己的，画面是用户给的一张图片，手势跟着内容走。分两个阶段，前一阶段的产物是后一阶段的输入：

| 阶段 | 做什么 | 用户要给的 | 产物 | 怎么做 |
|---|---|---|---|---|
| 1 配音 | 用用户自己的声音把文案念出来，并得到逐词时间 | 文案；10–20 秒人声样本（复刻过就不用再给） | 配音、逐词时间 | 读 [references/voice/guide.md](references/voice/guide.md) |
| 2 数字人 | 让一张图片开口说话，手势跟着内容走 | 一张人物图片 | 人物视频（带原声）、异常时间段清单 | 读 [references/avatar/guide.md](references/avatar/guide.md) |

两份说明都很长，**做到哪一阶段再读哪一份**，不要一次全读。两个阶段怎么通过项目目录交接、中断后怎么接着做、改了配音后人物视频要不要重做，读 [references/pipeline.md](references/pipeline.md)。

本技能到人物视频为止：最后一步是跳剪（剪掉说话之间的停顿）；**底部字幕是附加功能，问过用户、用户说要才加**。分段时间轴、图形动画、音效、画中画这类包装不在范围内：用户要的话，做完后告诉他可以交给 oldx-oneshot 的包装阶段或 visual-broll-director（项目目录直接通用），不要自己动手做。

文中的脚本路径都相对本技能目录。每个脚本的参数、产出文件、退出码和机读结果（`--json`）见 [references/tools.md](references/tools.md)；要直接调用这些脚本的 agent 先读它。

## 开始之前：弄清场景和范围

**场景**决定配音的语气和动作的方向。同一套流程可以做直播带货、知识口播、产品介绍、课程讲解，差别都写在 [references/scenarios.md](references/scenarios.md)，开始前读一遍，按文案内容和用户的话判断是哪一种。看不出来、几种理解差别又大时问一句；否则自己定，在交付时说明选了哪一种。

**范围**：不是每个人都要两个阶段都做。

- **只给了文案，要一条人物视频** → 两个阶段依次做完。
- **只要配音** → 只做第一阶段，做完就交付。
- **自带配音或录音，要人物视频** → 先补逐词时间（做法见 `references/pipeline.md` 的“用户从中间进来”），再做第二阶段。
- **以前做过，现在要接着做、要改、要换图** → 先看进度：

  ```
  python scripts/status.py          # 最近一个项目走到哪了、下一步是什么
  python scripts/status.py --list   # 所有项目
  ```

  按它给的 `stage` 和 `next` 接着做，不要从头来——前面的阶段是花过钱的。

拿不准用户要哪一段、而且做错了代价大（比如会花钱生成人物视频）时问一句；否则按最完整的理解做。

## 一次把要的东西要齐

两个阶段各自都要向用户要东西。两个阶段都做时，**在最开始一次问齐**，不要做到一半再回头打断用户：

1. **文案**（已经给了就不问）。
2. **声音**：以前复刻过就说“沿用你上次的声音”；没有就要一段 10–20 秒、干净的正常说话录音。
3. **人物图片**：近景、半身、站姿、全身都可以，会按图片类型编排动作。嘴闭着、表情平静、双手自然放在身前或桌面的图接缝最干净。要在视频里展示商品的，商品必须已经在图里（手里拿着，或摆在桌面、身旁）。
4. **配音试听默认停下确认**：展示当前版本的试听文件、语气和时长。用户明确说“不用试听”时，按阶段钩子记录真实原话并跳过 voice；没有回答就等待。只做配音时在这一站交付。
5. **要不要自动加底部字幕**（附加功能）：文字是原文案，烧进视频，另给一份 .srt。默认不加；他说要才加。这里没问到或他没回答，就在跳剪前请他确认人物视频时一起问，不另外多停一次。

用户已经给了的不再问；缺的那几样一条消息问完。

两个密钥（百炼、RunningHub）也在开头一起查：

```
python scripts/voice/check_key.py
python scripts/avatar/check_setup.py
```

RunningHub 只要 Key：生成人物视频用的云端应用已经内置，**不要向用户要应用 ID**。

缺哪个就按对应阶段说明里的原话向用户要，用户**只需要把密钥粘贴到对话框**，保存和后续操作都由你来做。只做配音时不用查 RunningHub。

## 缺什么自动装什么

这个技能要用到的 Python 包和 ffmpeg，本机缺了就**直接下载安装，不用问用户**。用户要的是视频，不该被“要不要装某个库”打断。

```
python scripts/setup_env.py                  # 两个阶段都做时，开头跑一次
python scripts/setup_env.py --stage voice    # 只做某一阶段时只装那一阶段要的：voice / avatar
```

- 输出里的 `installed` 是这次新装的：装完用一句话告诉用户装了什么，不用等回复，接着做。
- `failed` 是没装上的（退出码 7）：把里面的 `tell_user` 转告用户。常见的是网络问题。
- 中途哪个脚本报“缺某个模块”“找不到某个命令”，也是同样的处理：先跑一遍 `setup_env.py`，还缺就用 pip 把它装上再重试，而不是停下来问。
- **只装这个技能自己要用的东西**，装在当前 Python 环境里。不动系统设置，不升级用户已有的软件。
- 这条规则**不包括密钥和花钱**：密钥只能由用户提供；提交生成人物视频前仍然要报费用。

## 流程

1. **弄清场景和范围、要齐东西、查密钥、把环境装齐**（上面三节）。
2. **配音**：先展示并记录 inputs 确认，再按 `references/voice/guide.md` 做到逐词对齐和核对（主要就是 `scripts/pipeline.py voice` 一条命令），语气和情绪标签按场景定。做完展示试听文件、时长、语气和核对结果，记录 voice 确认或用户明确免试听的原话，再进入下一阶段。
3. **数字人**：按 `references/avatar/guide.md` 做到拼接和质检（分段用 `pipeline.py segments`，拼接和质检用 `pipeline.py finish`）。Hermes 本机先展示整条实际段数、时长、动作和生成范围，用户点击生成后由后端执行，不估价。仅非 Hermes 独立运行或显式 legacy 模式按其费用说明确认。质检发现问题时先展示问题与新方案，不能将新提交当作免费重试。
4. **跳剪**：质检没问题后，先展示 `final_avatar.mp4`、时长和质检结果，等待用户确认成片并同意跳剪；用户已明确免看片时按钩子记录跳过。用 `review.py approve video` 记录真实原话后，再运行 `scripts/avatar/jumpcut.py --workdir <workdir> --yes` 剪掉停顿。用户要改某一段，就先改、重新拼接质检，再展示新版。开头没问过要不要字幕的，在这一站一起问。
5. **字幕（附加，用户说要才做）**：`scripts/avatar/captions.py --workdir <workdir> --yes`，给跳剪后的成片烧底部字幕（规则见 `references/avatar/guide.md` 第 7 步）。用户没说要就跳过。
6. **清理，然后交付**：先 `python scripts/cleanup.py --workdir <workdir> --yes` 清掉随时能免费重新生成的文件（质检图、旧配音版本等，成片和花钱生成的片段不动）。成片是 `<workdir>/avatar/final_jumpcut.mp4`，加了字幕的是 `final_subtitled.mp4`（另有 `subtitles.srt`）；没剪停顿的 `final_avatar.mp4` 留着（后期包装用它的时间轴）。按下面的格式汇报。

以上直接脚本序列属于独立/legacy 指南；Hermes 本机通过客户端与受控 API 执行。四个阶段确认点按上方当前约定执行，免费准备工作可自主完成。

## 要停下来等用户的地方

| 什么时候 | 为什么 | 怎么说 |
|---|---|---|
| 本机没有某个密钥 | 没有就做不了 | 用对应阶段说明里的原话，让用户粘贴到对话框 |
| 配音做完（用户在开头选了要听） | 配音一改，已经生成的人物视频就作废、要重新花钱 | 给出试听文件和各段数据，等用户说可以 |
| 提交生成人物视频之前 | 确认整条实际范围及当前配音，避免重做错误版本 | Hermes 本机只展示段数、动作、时长与生成范围，配音未确认则先试听；记录 voice 与 generation 后，由实际生成按钮产生 `generation_consent`。不展示预计 RH 币、报价或预算。独立/legacy 的金额步骤按其适用配置执行；免试听只跳过 voice |
| 图片会被明显裁掉头顶或手，或 `prepare_image.py` 报了风险（`risks`：偏糊、过暗、透明背景、头顶贴边、脸太小……） | 生成出来救不回来 | 把裁剪预览的情况和风险告诉用户，让他换图或确认 |
| 文案要展示商品，图里却没有 | 提示词变不出图里没有的东西 | 告诉用户换一张带商品的图，或接受只说不展示 |
| 人物视频拼好、质检做完，跳剪之前 | 跳剪后再改某一段要从拼接重来；先让用户确认画面没问题 | 给出 `final_avatar.mp4` 的路径、时长和质检结果，问用户视频有没有问题、能不能开始跳剪；开头没问过要不要字幕的，一起问 |
| 同一段补救了 2 次仍有问题 | 再跑还是花钱，结果多半一样 | 如实说明问题和时间点，由用户决定 |

四个阶段确认点之外，不为“配音拆成几段”“人物视频在哪断开”“某句配什么手势”逐项提问；先形成完整方案，在 generation 确认点一起展示。

## 贯穿两个阶段的规矩

这些规矩在各阶段的说明里都有，放在这里是因为它们跨阶段、最容易在衔接处被忘掉：

- **密钥不回显，也不去聊天记录、日志、配置文件里翻。** 只说“找到了，来源是……”；本机没有就问用户。翻记录等于绕开用户。
- **不改文案。** 不润色、不增删、不纠错字；配音念的、提示词里的台词都是原文。价格、数量、型号、功效尤其一个字不动。发现可疑的地方在交付时提出来，由用户决定。
- **不改图片内容。** 只按比例裁剪，不美化、不换背景、不往图里加商品。
- **先判断图片类型，再写动作。** 图片类型决定能做哪些动作，文案场景决定选哪些、做多大；顺序不能反。
- **图里没有的东西不写进动作。** 商品、道具只有已经在图里才能拿、举、展示；也不用比喻，模型会把比喻里的东西画出来。
- **不做调速，音频只能由合成生成。** 配音就是合成出来的原速，本技能没有加速、减速的功能。用户嫌快或嫌慢时，告诉他这一点；可以试着在 `emotions.json` 的 `instruction` 里写“语速较快”“语速放慢”重新合成，但实测效果有限（同一段英文改成“语速较快”后从 37.2 秒变成 38.3 秒，没有变快）。不要用 ffmpeg 等去改 `out/`、`avatar/` 下的音频：停顿和切点对不上，视频里会有明显的停顿；后面的脚本也会核对音频指纹，改过就拒绝往下走（退出码 1）。 顺序固定为 合成 → 逐词对齐 → 分段 → 生成。
- **音频和时间文件一律不手工改，照着脚本给的 `next` 做。** 你处理不了音频，也不需要处理：找停顿、对齐、切段、核对都由脚本完成。不要手工编辑 `timeline.json`、`words.json`、`plan.json`、`merged.wav` 这类文件——想改什么，`references/tools.md` 的“想做什么 → 用哪个参数”表里都有对应参数。脚本因为缺指纹或时间对不上停下时，按报错重跑上一步。运行环境跑不了脚本时停下告诉用户，不要用估算的时间代替。
- **确认写在代码里。** 本机钩子用 `review.py approve/skip` 保存真实原话及素材版本，提交时衔接原有 `voice_review.json` 检查；确认过期就停下。仅使用旧项目原始脚本接口时仍保留 `--voice-approved` 的原有检查，不能借此绕过已启用的阶段钩子。交付时引用用户真实确认的原话。
- **花钱的脚本都是默认只预览、加 `--yes` 才执行**（复刻音色、合成配音、语音识别、生成人物视频）。先预览，看清要花在哪，再加 `--yes`。
- **环境缺的自动装，钱和密钥不自动。** 依赖、工具缺了直接装并告知；花钱的操作和密钥仍然要用户点头或提供。
- **不擅自升级付费档位。** 人物视频只用用户授权过的实例；显存不足或失败时报告，由用户决定。
- **旧片段不丢，挑最好的一版。** 重跑某段时旧片段自动收进历史（`takes.py` 可以换回），不要为了“留一份”手工复制目录，也不要为了挑选重新花钱生成。
- **用户说改过云端工作流，先记一个版本标签**（`check_setup.py --set-workflow`）再提交；排查画面问题时先问工作流有没有改过。
- **重跑时至少换一样：种子或提示词。** 同样的输入加同样的种子，重跑得到同样的结果，还要再花一次钱。先用 `--seed random` 换种子，同一处还出问题再改提示词；每段最多补救 2 次。
- **改完人物视频要重新请用户看、再跳剪。** 换了历史版本、重跑了某段之后，`finalize.py` → `qa_video.py` 重跑，请用户再看一次，确认后 `jumpcut.py`（加了字幕的还有 `captions.py`）再跑一遍，成片才是新的；之前的确认会自动作废。
- **字幕是附加功能，问过才加。** 用户没说要字幕就不加；文字用原文案，不改字。用户要别的语言的字幕（例如英文配音配中文字幕）时，译文由你写成 `avatar/translation_<语言>.json`，用 `captions.py --translation`，交付时请用户核对译文。
- **磁盘只清能免费重新生成的。** 交付前跑 `cleanup.py --yes`；配音缓存、人物视频历史版本、手工留的实验目录删了要再花钱或找不回来，只报大小，用户说要清才加 `--cache`、`--takes`、`--archive`。
- **只对看过、量过的东西下结论。** 你听不了声音、也看不了连续播放的画面：数据核对过的说“已核对”，没法验证的（音色像不像、口型准不准、语气合不合场景）明确交给用户。

## 交付时怎么说

先给结论，再给依据，用中文，不堆过程：

- **一句话结论**：实际成片在哪、多长、什么尺寸、几段，以及是否已执行用户选择的去停顿和字幕。Hermes 本机默认不展示报价；独立/legacy 仅在真实账单已知时可补充金额，未知不能写成免费。
- **跳剪一行**：从多长剪到多长、几个剪辑点；画面跳得明显的剪辑点有哪几个时间点；引用用户确认跳剪时说的话。
- **字幕一行**（加了才写）：几条、放在画面多高、停留特别短的几条；字号和位置请用户在手机上看一眼。是译文字幕的，说明译文是你写的、请用户核对。
- **清理一行**：腾出了多少；缓存、历史版本、实验目录还有多少可以清。
- **配音一两行**：按哪种场景定的语气，几段，文字核对结果，剪掉了哪几处多余语气词。
- **人物视频一两行**：每段多长、断在哪；质检发现了什么、重跑过哪几段；`anomalies.json` 里还剩哪些时间段。
- **需要用户自己确认的**：音色、语气合不合场景、口型、手势；带货文案里价格和数字的读法（给出时间点）；图里有商品时，商品在视频里有没有变样。
- **文案里可疑的地方**（像问句却用了句号、疑似错字、价格前后不一致），如果有。
- 还要加分段时间轴、图形动画的话，提一句可以交给 oldx-oneshot 的包装阶段或 visual-broll-director。
- 密钥在聊天里出现过的话，提醒一句建议重新生成。
