# Hermes 个人知识库接入（开发版，未上线）

只用于主 `hermes`，不改 `Hermess2` 或原生 Hermes 知识库。可信发送者来自实际网关事件，不接受模型 / 文本指定 owner。后台会核对启用人员、本人私聊渠道及个人账号；平台管理员没有个人资料读权限。

## 私聊指令

- 单独发送 `https://mp.weixin.qq.com/s/...` 或 `https://weixin.qq.com/sph/...`：收集来源。公众号尝试公开正文，视频号链接本身不等于原视频。
- `收藏到我的知识库：链接`：显式收集。
- `收藏笔记到我的知识库：正文`：最多 4000 字符，不调用模型。
- `我的知识库搜索：关键词` / `我的知识库问：问题`：本人原文检索，不自动调用付费模型。
- `我的知识库状态：资料编号`：查看本人状态。
- 私聊发送附件并配文字 `收藏附件到我的知识库`：最多 5 个适配器缓存文件，保存原件，不自动 OCR / ASR。
- `我的知识库附件收藏：开启` / `关闭`：开启后 10 分钟内私聊附件自动保存原件。进程重启即关闭；普通未开启私聊与群聊不采集。
- `我的知识库语义问：问题`：仅确认配置、返回费用与发送范围说明，不发送问题给模型。
- `确认语义检索：确认码`：本人同一私聊、5 分钟内一次性同意后，发送问题到向量模型并预留额度。只能检索本人主动建立的当前正文索引。

原生微信 SILK 语音可保存原件。本地解码需后台另外启用并安装兼容 `pilk`；不懒安装，不调用 Hermes 的自动 STT，不拿 OCR / TTS 密钥替代 ASR 权限。

附件缓存路径只来自已安装适配器 `MessageEvent.media_urls`，并限于官方缓存目录；不从聊天文字接收本机路径，不删除 Hermes 缓存原件。去重记录保留在后台，移除原资料后同一附件消息不恢复。超时结果未知时不会自动重放。

## 完成通知

`notification-routes.example.json` 是合并到现有 `platforms.webhook.extra.routes` 的样例，不能覆盖现有 routes。需将样例 secret 替换为服务器本地生成的独立共享密钥，并同步到后台 `TASK_KNOWLEDGE_NOTIFICATION_WEBHOOK_SECRET`。不要把密钥发到聊天或客户端。

主实例已安装源码确认 QQ 实际平台是 `qqbot`，微信是 `weixin`，企业微信是 `wecom`；后台既有人员渠道名 `qq` 在插件中做可信枚举映射。只启用实际运行的渠道路线；企业微信 callback / 未部署渠道需单独核查，不自动别名混用。

路线固定平台，动态 `{recipient_id}` 只来自后台校验过的本人 StaffChannel。`deliver_only: true` 把状态文字直接投递，不触发 LLM。正文 / 标题 / 文件名不进入通知。

后台使用 timestamp V2 HMAC 与 `X-Request-ID`。只有 `delivered` 且 delivery ID 对应才标为发送成功；`duplicate`、`accepted`、读取超时不能证明已送达，标为未知，人工确认风险后才重发。关闭或已读会取消未发送的 pending；已经发出的通知不可撤回。

后台 dispatcher 与 Hermes 路线配置默认未启用，本 README 不代表已安装或验收通过。
