# 管理员按成员设置频道订阅

当前状态：本地候选实现与本地验证完成，待用户验收；遵循“先不发布”，未部署正式后台、安装客户端或发布更新源。源码版本仍为 0.6.8，没有为此生成新版安装包。

交付入口：[可交互演示原型](prototype.html)、[桌面原型图](prototype-desktop.png)、[紧凑窗口原型图](prototype-compact.png)、[测试报告](TEST-REPORT.md)、[当前源码及构建散列](source-manifest.json)。原型使用演示数据，演示保存不会访问正式后台。

## 需求与设计

管理员在「用户管理 → 管理成员 → 频道订阅」为该成员勾选或取消实际订阅。保存后成员无需再次自行订阅，按频道既有时间接收新情报。取消订阅后不再发送对应新推送。

沿用迈医协同独立 Electron/React 工程 `D:/maiyi/SignalDesk` 及其 FastAPI 后台；本次不修改患者端或医疗管理系统的 Vue/Java 工程，不增加平台。复用现有 ChannelSubscription、微信绑定和频道权限，无数据库迁移或新依赖。既有个人订阅接口沿用同一写入规则。

| 验收 ID | 可观察结果 | 验证入口 |
| --- | --- | --- |
| AC1 | 管理员选择成员，读取该成员真实订阅，批量开通和取消 | 后端接口、弹窗测试、Electron 运行 |
| AC2 | 成员的个人频道目录立即体现代订阅结果，其他成员不变 | 实际 HTTP 与客户端 |
| AC3 | 非管理员、服务密钥、匿名请求无法代订阅 | 后端认证测试 |
| AC4 | 新订阅需成员启用、有频道页面权限、有效微信、频道开放且未暂停 | 后端边界与界面禁用原因 |
| AC5 | 已暂停/成员停用的已有订阅可取消；无效批量请求不部分写入 | 后端原子性测试 |
| AC6 | 并发订阅编辑、微信换绑后保存旧表单返回冲突，不覆盖新状态 | 快照测试、界面重试测试 |
| AC7 | 合并栏目仅列汇总频道；重复保存不重置订阅时间 | 后端兼容与幂等测试 |
| AC8 | 加载失败、保存失败保留选择，可重试；保存时防重复提交 | 组件测试、运行验收 |

界面沿用用户截图的绿色按钮、白色面板和原生 dialog，单独保存频道订阅，不提交或丢弃用户资料草稿。未开放权限时引导管理员到智能频道的「订阅权限」开放该成员；不自动扩大订阅资格。

## 源码与运行

- `src/components/MemberManagement.tsx`：管理成员中的入口。
- `src/components/MemberSubscriptionsDialog.tsx`、`member-management.css`：逐频道选择、原因和重试。
- `src/lib/articleApi.ts`：成员订阅读取与保存契约。
- `server/app/channel_subscriptions.py`：管理员 GET/PUT `/api/v1/channel-subscriptions/members/{staff_id}`。
- `server/tests/test_channel_subscriptions.py`、`src/components/MemberSubscriptionsDialog.test.tsx`：复用原测试工程。

请求包含原订阅列表、所选列表和微信绑定版本；服务端在事务内锁定频道/订阅/绑定，验证全部新增项后统一保存。管理员授权与成员订阅资格分别检查。旧后端未提供该接口时，客户端明确提示需更新后台。

工程启动：在 `D:/maiyi/SignalDesk` 执行 `npm run dev`；Web 构建：`npm run build:web`，输出为主工程 `dist/`。后端按工程既有 Uvicorn 配置启动。本地隔离验收可执行 `node scripts/member-subscriptions-e2e.mjs`，自动创建独立测试库和测试账号，不连接正式订阅数据。证据在此目录，隔离运行数据在工程 `artifacts/admin-member-subscriptions-20261120/`。

## 测试跟踪与已发现问题

- 当前验证：后端 47 项通过、前端 218 项通过、类型检查通过、Web 构建成功；真实 Electron 联动隔离后台的 5 项验收通过。完整范围、时间、失败与复测见测试报告。
- 新组件首轮 5 项失败：JSDOM 未实现原生 showModal/close，已在测试中补齐桩并复测通过，不修改产品行为。
- 后端首轮在 TestClient 启动前挂起。25 秒故障栈定位到 Windows asyncio socketpair 的本机 accept，属于受限环境的回环网络问题；使用获准的本机网络环境后完整运行通过。
- 历史测试目录包含 artifacts 中旧候选源码，当前版本 Vitest 显式排除 artifacts，避免以旧代码测试冒充本次验证。
- 发现保存请求迟到导致跨成员回调的问题，增加请求世代检查；失败用例与最终通过记录已保留。
- 原生窗口发现长列表将底部按钮挤出弹窗，修复表单网格和滚动区域；原失败断言复测通过，桌面及紧凑窗口图已核对。

## 发布与验收边界

当前授权落实为代码、构建和实际本地验证。正式部署、客户端安装/更新源发布尚未执行；不能把本地构建称为已上线。本次不向真实成员发送微信，也不修改正式订阅数据。

验收时可打开演示原型勾选频道并演示保存；实际联动已由隔离 Electron 用例验证。用户尚未验收。真实微信投递、正式 MySQL 并发运行及正式 Windows 安装包升级未执行，需后续发布授权和相应环境才能补验。

后续发布时应先发布兼容后端接口，再更新客户端；旧后端会明确提示接口不可用。回退前保留部署版本和数据库备份；本次不需要数据库迁移，回退客户端不会删除已保存订阅。

复盘：本次把成员身份变更时的迟到请求和真实原生 dialog 布局纳入回归，避免只以组件测试和构建判断可用。复用原订阅规则与测试工程，无新增依赖。
