# Hermes 首次绑定入职引导

需求：新人首次绑定 Hermes 后，先收集“希望怎么称呼助手”“助手怎么称呼本人”，再按编号选择频道，保存真实订阅，最后给出中文操作指南和可直接使用的语句模板。通用行为同步 default，保留既有成员数据、天气城市和原生授权/复制逻辑。

范围为现有微信私聊、Hermes 档案插件及迈医 FastAPI 订阅接口，不增加 PC、小程序或手机 App 界面。微信扫码后首条本人私聊触发引导；未收到入站消息前不承诺主动欢迎一定能投递。会话状态设计承担原型职责，无新增前端控件。

对话原型（演示）：

1. 新人：你好。
2. Hermes：欢迎使用迈医助手。你希望给我起什么名字？例如“小迈”，回复“默认”使用 Hermes。
3. 新人：小迈。
4. Hermes：以后你可以叫我“小迈”。我应该怎么称呼你？例如“小陈”或“陈老师”。
5. 新人：陈老师。
6. Hermes：陈老师，选择你想订阅的频道：1. AI 决策雷达；2. 医疗前沿频道。回复“1”订阅第 1 项，回复“1,2”订阅两项；回复“0”暂不订阅。（实际内容来自该成员有资格订阅的频道）
7. 新人：1,2。
8. Hermes：确认后台保存成功后说明所订阅频道，再给出任务、天气城市、频道订阅、办公草稿等操作模板。回复“操作指南”可再次查看。

状态：未开始 → 助手名字 → 本人称呼 → 频道选择 → 完成。支持“稍后”暂停、“入职引导”继续；“绑定迈医”指令始终交给现有扫码绑定插件。没有关联迈医成员账号时，说明原因并允许暂不订阅，不使用昵称冒充后台成员身份。

| AC | 验收条件 | 实现/验证 |
|---|---|---|
| AC1 | 首次本人私聊依次收集两种称呼；老成员升级不被重新询问 | 档案本地状态、原生 hook |
| AC2 | 称呼持久化、重启继续；不同成员隔离；复制后的新档案按自身身份引导 | 状态/派生 SOUL 提示与原生档案测试 |
| AC3 | 频道按编号展示；支持单选、多选、跳过；仅显示可订阅项 | 真实目录接口、会话测试 |
| AC4 | 选择实际保存至本人订阅；保留管理员已有订阅；无权、旧快照、微信换绑原子拒绝 | 服务端接口与隔离 HTTP 联动 |
| AC5 | API/文件保存失败不宣称成功，允许重试；重复消息不重复推进或重复订阅 | 持久化、重放和失败用例 |
| AC6 | 群聊、其他人、内部/机器人消息不能修改个人设置或订阅 | 原生入站边界测试 |
| AC7 | 全中文操作指南可重查；模板来自现有功能；不扩大办公或工具授权 | 指南内容与真实路由检查 |
